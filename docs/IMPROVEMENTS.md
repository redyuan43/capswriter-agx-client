全部数字来自**真实音频 + 真实腾讯云 ASR**，不是合成用例。

验证环境：腾讯云 ASR 服务 `ai-x10drg:18011`（Tailscale `100.91.42.28`），
数据集 `~/Documents/CapsWriter-Voice-Dataset`（3786 条真实录音）。

## 二、逐项说明

### 1. ASR 热词表（核心收益）

**问题**：腾讯 ASR 对中英混合专有名词识别很差，尤其会把缩写逐字母念错：

```
Tailscale  → "tell" / "tellle"
GitHub     → "G他" / "这个号" / "其他不"
ADB        → "a DB" / "ADP"
```

**做法**：从 3786 条数据集自动挖掘高频术语，按频次取前 128 个（腾讯上限），
按频次分级赋权重（≥10 次 → 11；4–9 次 → 8；≤3 次 → 5）。
词表落在 `~/.config/语音转写/hot-words.txt`，格式 `词|权重`。

**效果**（大样本：8 个术语 × 每术语 14–20 条，共 153 组同样本对照）：

| 术语 | 样本 | 基线 | 热词 | 差值 |
|---|---:|---:|---:|---:|
| Tailscale | 20 | 0% | 30% | **+30pt** |
| AGX | 19 | 63% | 95% | **+32pt** |
| Codex | 14 | 57% | 79% | **+21pt** |
| GitHub | 20 | 50% | 55% | +5pt |
| ADB | 20 | 65% | 70% | +5pt |
| APP | 20 | 90% | 95% | +5pt |
| TTS | 20 | 95% | 95% | 0 |
| WiFi | 20 | 100% | 100% | 0 |
| **合计** | **153** | **65%** | **77%** | **+12pt** |

配对结果：纠正 21 条、回归 3 条、无变化 129 条。

**诚实说明**：
- 此前 34 条小样本测出的 **+21pt 偏乐观**，大样本真实值是 **+12pt**。
- 已经识别得很好的词（TTS 95%、WiFi 100%）加不加都一样 —— 热词不会伤害它们。
- **GitHub 存在双向抖动**：20 条里纠正 3 条、回归 2 条，净 +5pt。权重 11 在个别样本上
  会过拟合（"提交代码的，其他不上去"）。若在意可把 GitHub 权重降到 8 再测。

**典型纠正**：
```
基线: 可可能需要使用tell的路径去拷贝。      → 热词: 可能需要使用tailscale的路径去拷贝。
基线: 提交代码到G他上去。                    → 热词: 提交代码到github上去。
基线: 帮我到g hub上面去。                    → 热词: 帮我到GitHub上面去。
```

### 2. 热词链路断点修复

原来剪贴板捕获术语后必须调 `POST /api/hotwords/learn`，但**腾讯-only 服务没有这个路由**，
导致学到的词全部丢失、`sessionHotwordsRef` 永远为空 —— 管道通了但没水。

改为**本地优先**：学到的词先写 `~/.config/语音转写/hot-words.txt`，一定生效；
服务端 learn 降级为 best-effort（失败不影响本地）。

### 3. hot-rule.txt 文本后处理

移植老 CapsWriter 的 51 条规则，并针对"ASR 逐字母念缩写"新增 4 条（APP / APK / GitHub / AGX），
现共 55 条。在 3786 条真实样本上：**21 次命中，全部正确，0 误伤**。

### 4. CT-Punc 标点恢复 —— 结论是「不要用」

实测 FunASR CT_Transformer 对腾讯 ASR 输出是**净负收益**：
- 吞掉中英之间的空格
- 删掉腾讯已经标对了的标点
- 把数字切断（`18081` → `180。81`）

因此**保留接线但默认关闭**。若将来换 ASR 引擎（输出不带标点）可再启用。

### 5. knob mapper 日志刷屏

**根因**：默认 `knob_mapper_enabled = true` → 启动 `knob_mapper.py` → 缺 PyYAML 立即崩溃 →
`close` 事件触发 2 秒后自动重启 → 无限循环。单次启动产生 **704 条**日志，淹没真正有用的信息。

**三层修复**：
1. **依赖预检**：启动前 `python3 -c "import yaml"`，缺失直接跳过，根本不 spawn
2. **重启上限**：连续秒退超过 2 次后停手（进程存活 < 3s 判定为启动失败）
3. **显式关闭**：本机数据库已写入 `knob_mapper_enabled = false`

修复后日志从 704 条降到 **0 条**（依赖缺失时）或最多 3 条（其他失败）。

恢复方法：`pip install pyyaml` 后把 `knob_mapper_enabled` 改回 `true` 即可，无需改代码。

### 6. M5 / Cardputer 数据集采集

外部设备录音完成时补上 `recordExternalVoiceSample`（source `external_m5`），
此前只有本地键盘录音会进数据集。

## 三、成本

大样本验证消耗 **约 38 分钟**免费额度（306 次请求，同一批音频跑两组）。

热词是**腾讯服务端推理时生效**的特性，本地无法模拟，因此对照实验必须跑真实 ASR ——
离线数据里不存在"同一条音频的带热词版本"。基线数据可复用存量以省掉一半请求。
