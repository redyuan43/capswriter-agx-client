## 二、Major（需修改后重审）

### [major] `buildKillerScript` 的 starttime 校验链短路 → pid 复用防护在异常分支失效

- `src/helpers/quitWatchdog.js:62`：
  `[ -n "$expected" ] && [ -n "$actual" ] && [ "$actual" != "$expected" ] && exit 0`
- `expected` 来自 `readProcessStartTime`，读失败时返回 `""`（`:50-52`）；`actual` 由 `sed|cut` 解析得到（`:61`）。**任一为空 → 整条 `&&` 链为假 → 不 `exit 0` → 直接落到 `kill -9 "$pid"`**
- 后果：pid 复用防护在最需要它的异常分支上退化为「到点无条件杀该 pid」；若原进程已退出且 pid 被系统复用，可能误杀无关进程
- 测试缺口：`test/quitWatchdog.test.js:284` 只断言 `!=` 子串存在，未覆盖空值分支，因此测不出
- 判据：AI 典型失效③「抽象边界条件缺失」+ §3.1 B5 精神（不得造成数据/进程层面的静默破坏）
- 建议动作：改成失败即放弃击杀的显式短路，并补空值分支断言：
  `[ -z "$expected" ] && exit 0` / `[ -z "$actual" ] && exit 0` / `[ "$actual" != "$expected" ] && exit 0`

### [major] 「主动退出标记」30 秒窗口会静默拒绝用户的手动重启

- `scripts/install-linux-client.sh:258-263`、`scripts/deploy-nx6-appimage.sh:117-121` 生成的启动器：
  `if [ -f "$QUIT_MARKER" ] && age < 30 → exit 0`
- `markIntentionalQuit` 在**每次** `before-quit` 都写标记（`main.js:1237` 调用），启动器无法区分「systemd 自动拉起」与「用户又点了一次图标」。用户退出后 30 秒内手动启动会**无任何输出地直接退出**，表现为「点了没反应」
- 注释与实现不符：`scripts/install-linux-client.sh:257` 写「更晚的手动启动照常，并顺手清掉过期标记」，30 秒内的手动启动并不照常
- 判据：§5「构建与发布脚本」需 L2 必做；可观测性 M5
- 建议动作：只在服务被调用时抑制（`systemd` 会注入 `INVOCATION_ID`），手动启动放行；被抑制时向日志写一行原因

### [major] 清理 `/tmp/appimage_extracted_*` 的删除范围过宽

- `scripts/install-linux-client.sh:254`、`scripts/deploy-nx6-appimage.sh:122`：`rm -rf "${TMPDIR:-/tmp}"/appimage_extracted_*`
- 通配命中的是**所有** AppImage 的 extract-and-run 解包目录，而前置的 `pgrep -f "$APPIMAGE_PATH"`（`:248` / `:115`）只判断本客户端是否在跑。注释「上面的 pgrep 检查会提前 exit，不会误删正在使用的目录」**不成立**：另一个正在运行的 AppImage 的解包目录会被删掉，可能导致其崩溃
- 判据：破坏性操作缺少作用域约束（AI 失效③）
- 建议动作：删除前先判断该目录是否仍被进程引用（`pgrep -u "$(id -u)" -f "$dir"` 命中则跳过），或按本 AppImage 的固定解包目录名精确删除

### [major] `m5SerialDiagnose.js` 重复实现 + 零测试（M2 / M3）

- M2：`src/helpers/m5SerialDiagnose.js:30-31,37-45,79-89` 重复实现 `src/helpers/m5SerialProvision.js` 已有的 `SERIAL_BY_ID_DIR`、`ESPRESSIF_BY_ID_PREFIX`、`listEspressifPorts`、`openNonBlocking`（后者已 `module.exports`，`:361-364` 可用），且前缀常量已经分叉：诊断工具用 `usb-Espressif`，provision 用 `usb-Espressif_USB_JTAG_serial_debug_unit`，两处判定结果可能不一致

- 判据：M2「不得重复实现已有 helper」、M3「新增业务逻辑必须带测试」（新模块覆盖率 ≥ 60%）
- 建议动作：改为 `require('./m5SerialProvision')` 复用扫描/打开逻辑，把可测试的纯函数（端口选择、行缓冲、分类）导出并补单测
