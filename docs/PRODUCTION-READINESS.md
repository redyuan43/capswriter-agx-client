# 产品化就绪度评估（v1.0.21 基线）

- 评估日期：2026-09-20
- 评估基线：`v1.0.21-hotwords-weights`（工作区版本号 `1.0.21`）
- 评估方式：静态核对代码与构建配置，逐条附证据（文件 + 行号）

## 一句话结论

热词链路这次是真通了。但整体仍是**「自用能跑」**水平：别人装上连不上、出问题你看不到、修了 bug 送不出去。
三类共 17 个缺口，其中 **7 个是产品化硬阻塞**。

亮点先说：客户端源码里**不含任何腾讯云密钥**（密钥只存在于服务端 `services/tencent-asr/provider.py` 读环境变量），
这个安全边界划得对，产品化时保持即可。

## P1 — 产品化硬阻塞（给别人用就不能用）

| # | 缺口 | 证据 | 后果 | 建议 |
|---|---|---|---|---|
| P1-1 | **ASR 算力在私网 + 客户端零鉴权** | 服务仅监听 Tailscale `100.91.42.28:18011`（`services/tencent-asr/README.md:9`）；客户端只做协议适配、不做鉴权 | 别人装上连不上；且谁拿到地址谁就能烧你的腾讯云额度 | 公网入口 + `wss://` + API Key 鉴权 + 每用户配额 |
| P1-2 | **构建期把后端地址烧进产物，且烧的是失效地址** | `package.json:18` `build:linux:agx-client` 注入 `VITE_REALTIME_ASR_URL=ws://spark-31d6.taild500c8.ts.net:18011`；而实际服务在 `ai-x10drg:18011`，`spark-31d6` 已不通 | 现构建产物换网络/换机器即死；每条地址各一套构建脚本，不可维护 | 地址改为**运行时配置**；默认值指向正式入口；首启向导强制确认连通性 |
| P1-3 | **自动更新完全没接线** | `package.json:98` 依赖 `electron-updater@^6.6.2`；全仓库（排除 `node_modules`）grep `electron-updater\|autoUpdater` **零命中**；`build` 配置无 `publish` 字段 | 用户永远停在安装那一版；这次热词修复**一分钱都送不到用户手上** | 接 GitHub Releases update feed + 签名校验；设置页加「检查更新」 |
| P1-4 | **分发无签名、覆盖不足** | `package.json:184-191` Linux 仅 `AppImage`（无 deb/rpm、无签名步骤）；`:171-178` Windows nsis 无代码签名；`:160-170` mac `notarize.teamId` 写死为上游作者的 `7MTHK6DGS4`（**须确认归属**） | Windows 装机遇 SmartScreen 拦截；mac 无自有证书则无法签名公证；Linux 无包管理器安装路径 | Windows 上代码签名证书；Linux 补 deb；mac 换自有 teamId 或暂不发布 |
| P1-5 | **零错误上报** | 全仓库无 Sentry/自建上报接入；当前排障靠远程 CDP 调试 | 用户说「像狗屎」，你手上没有任何数据，只能复现 | 本地「一键导出诊断包」（日志+配置+版本+最近失败原因）+ 可选匿名上报 |
| P1-6 | **无成本护栏** | 腾讯 ASR 按量计费；客户端无限流、无日上限、无超限降级 | 一旦对外，额度可能被刷爆且无预警 | 单用户配额 + 超限降级到本地模型 + 用量告警 |
| P1-7 | **隐私与数据合规空白** | 录音默认进数据集（`recordExternalVoiceSample`，默认开）；日志可能含转写文本；无隐私政策、无保留期、无删除入口 | 对外分发存在合规风险 | 采集默认改为**关**；补隐私政策 + 数据保留期 + 一键清除 |
| P1-8 | **个人化词表随包分发** | `package.json:141` `assets/**/*` 打进产物；`assets/hot-words.txt` 含 `Ivan\|11`、`AMD\|11`、`Spark\|11` 等个人/设备词 | 你的个人语境随安装包发给所有人；同时别人的词表你也不知道 | 包内只放**通用技术词**；个人词表只留用户本地 config 目录 |

**第一批（小工作量、直接决定「修复能否送达」）**
1. P1-3 接自动更新 —— 不接，前面所有修复都送不到用户
2. P0-1 降级可见 —— 防止下一次静默失败
3. P0-2 热词 smoke test —— 锁住这次的根因

**第二批（对外分发的前提）**

4. P1-2 后端地址运行时可配 + P1-1 公网入口与鉴权（这两条一起做，否则产物仍是私网玩具）
5. P1-5 诊断包导出

**第三批（规模化）**

6. P1-4 签名与安装器、P1-6 配额、P1-7 隐私合规
7. P2-1 启动自检面板、P2-2 配置收敛

## 附：已确认做对的地方（产品化时保持）

- 客户端**零密钥**：腾讯云凭据只在服务端读环境变量，客户端拿不到
- 文本后处理有 `degraded` 机制（`src/platform/electron/textPolish.js`），链路降级不会整体崩
- CI 已有骨架：`daily.yml:44` 跑 `pnpm test`，`release.yml` 由 tag `v*-agx-client` 触发双架构构建 —— 缺的是「构建产物如何送到用户手上」
- 39 个单测 + 113 个源码文件，工程基础不算差，主要缺口集中在**分发与可观测性**
